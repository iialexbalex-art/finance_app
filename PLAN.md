План этого блока выполнен в коде:

4. Добавлены формы/истории доходов и переводов, общая фильтрация, отдельные

5. Подготовлены rollback SQL-тесты, выполнены Flutter-проверки и web build.

Технические решения:

- `save_income` / `save_transfer` проверяют владельца в базе, сериализуют запись
  с изменениями справочников/прав и сохраняют исходные квитанции. Повтор создания
  после правки возвращает прежний ID; конфликт revision отклоняется.
- `query_incomes` использует общую семантику расходов: рекурсивные ветви,
  архивные категории, включительные даты, курсор и итог всего выбора по валютам.
  `query_transfers` фильтрует любую сторону один раз, период и буквальную подстроку.
- Комиссия — один расход с `transfer_id`; при снятии становится `is_void`,
  исключается RLS из истории и расчётов. Возврат комиссии использует тот же ID.
  Публичная сигнатура `edit_expense` сохранена, комиссия направляется в перевод.
- Остатки учитывают будущие даты и все операции. Доходы/расходы не включают
  основной перевод. Комиссия вычитается только через расходы. Обзор получает
  все кошельки/остатки одним RPC со стабильным снимком, разные валюты раздельны.
- Существующий `expense_pending_v1` не изменён; доходы используют
  `income_pending_v1`, переводы — `transfer_pending_v1`. Ключ включает пользователя,
  пространство и request UUID; подтверждение удаляет только свой запрос.
- Телефон: прокручиваемое нижнее меню, содержимое выше безопасной границы.
  Десктоп: меню слева. У менеджера скрыты и запрещены доходы/переводы/остатки.
