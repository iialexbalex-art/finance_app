# Раздел «Отчёты»

Реализован в существующем приложении на схеме Supabase 013. Новых миграций нет. Пользовательские кошельки, категории, изображения, операции, остатки и локальные очереди запросов не изменяются.

## Возможности

- Пункт «Отчёты» в боковом и мобильном меню. Повторный выбор возвращает каталог.
- Три быстрых отчёта и все 11 остальных видов из задания.
- Общие фильтры пространства, периода, валюты, нескольких кошельков, категорий с потомками и текстового поиска. Настройки видны на экране; смена пространства сбрасывает кошельки и категории.
- Группировка по категориям, кошелькам, дням, неделям и месяцам. Сортировка по сумме, названию и количеству.
- Таблицы, столбцы, линии и кольца. Кольцо объединяет только на диаграмме категории после семи крупнейших; «Остальное» раскрывает их список. При отрицательных значениях используется представление со знаком и явным пояснением.
- Сравнение двух периодов, сопоставимый предыдущий отрезок, полный предыдущий месяц и произвольный период B; разница, изменение, количество и средняя сумма в день для разных длительностей. Дневные линии и нарастающий итог.
- Доходы, расходы и денежный результат; переход «месяц → дни → операции». Детализация сохраняет родительский отчёт и позицию прокрутки, имеет поиск и сортировку.
- Конструктор с именованными группами, индивидуальными фильтрами и общей датой сравнения. Пересечения отмечены; итог считается по уникальным операциям.
- Сохранение настроек, переименование и удаление шаблонов. Хранилище — браузерное, разделено по ID пользователя. Относительные периоды вычисляются заново. Между устройствами шаблоны не синхронизируются.
- CSV с UTF-8 BOM и настоящие OOXML XLSX с листами «Сводка», «Операции», «Параметры». Параметры содержат периоды, условия, валютную основу, часовой пояс, время формирования. Денежные ячейки числовые, даты — Excel dates; масштабы 0–4 поддержаны. Текст не превращается в формулы.

## Данные и расчёты

`lib/report_model.dart` — единый слой отбора и агрегации. `lib/reports_screen.dart` — интерфейс. `lib/report_export.dart` — экспорт из той же выборки; условный `report_download.dart` использует Web API только в браузере.

Отчёты читают существующие `query_expenses` / `query_incomes` с ключевой пагинацией до последней страницы и активным RLS. Доходы запрашиваются только в пространствах, которыми владеет пользователь. Ошибка любой страницы отменяет результат целиком. Запоздалые запросы не заменяют текущий отчёт.

Суммы агрегируются в `BigInt`; разные масштабы одной валюты приводятся к общему масштабу до сложения. Валюты не складываются между собой. Конвертация отсутствует, поскольку в проекте нет механизма курсов. `double` используется только для геометрии графиков, не для денежных итогов.

Обычные переводы не входят в доходы/расходы; комиссии берутся из сохранённых расходов без синтетического добавления. Начальные остатки и незавершённые локальные операции не читаются. Отменённые комиссии исключает существующая RLS-политика расходов. Архивирование справочников не исключает доступные исторические операции. Категории с именами «Корректировка» или «Возврат» не получают придуманной денежной семантики: отдельного структурного признака корректировок/сторно в текущей модели нет.

Даты операций в схеме — `date`, календарные компоненты пользователя. Они не преобразуются в UTC-моменты. Относительные даты используют локальный день приложения; обе границы выбранного календарного периода включены.

- `flutter analyze`: без замечаний.
- Полный набор `flutter test`: 189 тестов, включая 22 целевых теста отчётов.
- `flutter build web --dart-define-from-file=config/local.json`: успешно. После перехода на `package:web` проверка совместимости Wasm также проходит; отдельная сборка `--wasm` не выполнялась.
- Контролируемые расчёты: две валюты, отсутствующая категория, архив, границы дней, 1103 операции, большие точные суммы и разные масштабы, комиссии/изменение комиссии, периоды разной длительности и февраль високосного года, нулевая/отрицательная база, пересечения групп и соответствие детализации агрегату.
- Интерфейс: 1440×1000 и 375×900, все пункты каталога, фильтры, смена пространства, поиск/сортировка детализации, переход к дням месяца, сохранение/переименование/удаление шаблонов, изоляция пользователя, ошибка/повтор и запоздалый ответ.
- `tools/verify_report_exports.ps1`: независимая проверка ZIP/XML настоящего XLSX и CSV; 7 контрольных операций, три валютно-периодных итога, числовые суммы, даты, отсутствие формул и совпадение сводки с операциями.

Flutter запускался через `D:/dev/flutter/bin/cache/dart-sdk/bin/dart.exe D:/dev/flutter/bin/cache/flutter_tools.snapshot`, поскольку обычный запуск в ограниченной среде не мог записывать SDK cache. Логи и артефакты находятся в `build/reports_qa`.

## Непроверенные части

К автоматизации пользовательского браузера нет подключения: CUA вернул пустой список браузеров, попытка открыть Chrome — `Browser is not available: chrome`. Поэтому ручной проход реальной Supabase-сессии, реальные разрешения менеджера на сервере и скачивание через кнопку в этой сессии не подтверждены.

Дополнительный запуск тестов `--platform chrome` из готового SDK snapshot завершился ошибкой отсутствующего файла `C:\b\s\w\ir\x\w\archive\.pub-cache\hosted\pub.dev\test-1.31.1\lib\src\runner\browser\static\host.dart.js`. Повтор из исходников SDK обошёл этот путь, но завис на загрузке первого теста; остановлены только процессы этой временной тестовой сессии. Браузерные тесты не засчитываются как пройденные.

Снимки каталога, бизнес-расходов, детализации, сравнения и сохранённого отчёта в `build/reports_qa/*.png` получены из реальных Flutter-виджетов приложения с отдельным подставным репозиторием и контролируемыми данными. Это не снимки пользовательского журнала. Контрольные CSV/XLSX также содержат только тестовые данные.
