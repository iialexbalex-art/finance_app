## Выполнено и проверено

- Оригиналы по SHA-256: общий CAS встроенных assets, отдельный CAS приватных
  файлов владельца. Сжатые данные/manifest отдельно по snapshot ID.
  PUT условный `If-None-Match: *`, повтор принимает только идентичные байты.
- Перед ready проверяется содержимое S3 через потоковый GET и SHA-256,
  включая оригиналы. HEAD/ETag/кеш не заменяют проверку. Проверяется приватность
  ACL/политики. TLS, SigV4, path-style, таймауты/повторы настроены.
- Пустой кеш восстанавливается из S3. ZIP включает оригиналы без пересжатия;
  формат 1 / схема 18 и штатный Store.import_zip сохранены.
- Общая межпроцессная блокировка на одном VPS: ручной/ночной запуск, `--once`,
  экспорт, импорт, восстановление, регистрация и очистка. Запас диска 5 GiB
  плюс потребность операции. Передачи ограничены по времени.
- Маркированные временные каталоги очищаются при обрыве/на старте/tick под
  той же блокировкой. Чужие каталоги/симлинки/нужные оригиналы не удаляются.
  Снимки удаляются только по SQL-разрешённым ID с pins/ретенцией.
- `--once`: 0 = создана/реально проверена готовая копия; 1 = ошибка;
  2 = нет заданий/проверенной копии. JSON различает created/verified/existing.
  Проверяется heartbeat и живость scheduler; мёртвый поток не выдаёт next_run.
- Подготовлены systemd units с MemoryMax=1G, nginx, закреплённые зависимости,
  несекретный env, ограниченная IAM-политика S3 и точные команды установки.

**37 серверных тестов прошли.** Flutter: analyze без замечаний, 228 тестов
прошли, web build успешен. Проверены недоступное S3, неверный ключ,
AccessDenied/SignatureDoesNotMatch, прерванные PUT/GET, половина снимка и retry,
повреждение SHA при хорошем HEAD/кеше, публичные ACL/политика, неподдерживаемый
conditional PUT, безопасные сообщения, exit code CLI, overlap ручного/ночного
запуска, блокировка реальных процессов и освобождение после завершения процесса,
heartbeat/stale, нехватка диска, оборванный HTTP import, очистка/retention
и прежние защиты ZIP/владельца/ссылок/денег. Отказы инъецированы в тестовый
клиент S3. Настоящий boto3 дополнительно проверен через loopback HTTP endpoint,
включая отказ тестового ключа и недоступный сетевой endpoint.
Это не тест настоящего Timeweb.

## Ubuntu, диск и зависимости

Цель: Ubuntu **24.04 LTS x86_64**, Python 3.12, systemd/nginx.
Docker/панель хостинга не требуются.
[Release notes Ubuntu](https://documentation.ubuntu.com/release-notes/24.04/).
Все **11 wheels** зависимостей загружены с PyPI для CPython 3.12
manylinux2014_x86_64; `pip check` текущего venv успешен. Linux wheels
не исполнялись: `backups-preflight/LINUX_S3_WHEELS_20261007.json`.

40 ГБ достаточно для ОС, текущего кеша около 0,75 ГБ, сжатых снимков и временной
сборки при одной тяжёлой операции. Резерв 5 GiB — настройка защиты с запасом
под 2 GiB ZIP / 128 MiB файл, не измеренный текущий расход. Оригиналы хранятся
консервативно; следить за ростом кеша. ZIP целиком в RAM не загружается.
Объекты передаются одиночным PUT: multipart частей worker не создаёт.
Завершённые объекты оборванного снимка сохраняются для безопасного повтора.

## Проверки, требующие настоящего Ubuntu и Timeweb

Пока не выполнены из-за отсутствия ресурсов/защищённых реквизитов:

- TLS, настоящие ACL/IAM/HEAD/PUT/GET/DELETE Timeweb, conditional PUT,
  SHA readback, отказ/обрыв тестового префикса и запрет удаления оригиналов.
- systemd sandbox/cgroup-пики на FirstVDS с 2 ГБ, реальный диск/сеть/трафик,
  первый запуск, ZIP и перезапуск VPS.
- Ограниченный LOGIN worker к рабочей БД, регистрация assets, первая готовая
  копия, ручное сохранение и отображение в приложении.
- Защита перед изменениями и restore ZIP в отдельной тестовой PostgreSQL-среде
  с настоящим S3; рабочую БД для этого не восстанавливать.
- Настоящий ночной запуск 23:59 Asia/Qyzylorda и здоровье после перезапуска.

**Рабочие автоматические бэкапы пока не активны.** Подтверждённого следующего
запуска нет. Целевое время 23:59 +05 / 18:59 UTC.
