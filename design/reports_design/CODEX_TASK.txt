ЗАДАНИЕ ДЛЯ CODEX: РАЗДЕЛ «ОТЧЁТЫ»

Работай в существующем Flutter/Supabase-проекте D:\finance_app. Создай полноценный раздел «Отчёты» с быстрыми готовыми отчётами, настройкой фильтров, детализацией до операций, сравнением периодов и экспортом.

Перед началом прочитай правила проекта и изучи текущие маршруты, модели доходов/расходов/переводов/комиссий, денежные типы, пространства «Личное» и «Бизнес», права доступа и механизм работы с датами. Используй действующую архитектуру. Скриншоты в references — ориентир по логике, а не данные для импорта и не требование буквально копировать их оформление. Суммы со скриншотов не переносить в базу или production-код.

РЕЗУЛЬТАТ ДЛЯ ПОЛЬЗОВАТЕЛЯ

В левом главном меню появляется «Отчёты». Нажатие открывает каталог отчётов. Пользователь нажимает название и сразу получает рассчитанный отчёт с разумными настройками. Из суммы, категории или точки графика можно перейти к исходным операциям. Настройки и выбранный период видны, итог понятен, результат можно выгрузить.

Самый важный сценарий: «Отчёты» → «Расходы бизнеса». Одно нажатие на название сразу показывает бизнес-расходы с начала текущего месяца по текущий день. Предварительный мастер настройки не нужен.

1. НАВИГАЦИЯ И КАТАЛОГ

Добавь «Отчёты» в существующий sidebar и мобильное меню. Повторное нажатие на «Отчёты» из любого отчёта всегда возвращает к каталогу, даже если этот раздел уже выделен в меню. Внутри отчёта показывай понятную кнопку возврата и название.

Наверху каталога — готовые быстрые отчёты:
— «Расходы бизнеса» — основной, заметный пункт;
— «Доходы бизнеса»;
— «Личные расходы».

Далее размести полный каталог, сгруппированный по смыслу:
— «Доходы по категориям»;
— «Расходы по категориям»;
— «Структура доходов» — круговая/кольцевая диаграмма;
— «Структура расходов» — круговая/кольцевая диаграмма;
— «Сравнение доходов за периоды»;
— «Сравнение расходов за периоды»;
— «Доходы и расходы»;
— «Доходы по месяцам»;
— «Расходы по месяцам»;
— «Денежный поток по дням»;
— «Настраиваемый отчёт».

Последний пункт «Сравнение — Доходы / Расходы 2» со скриншота реализуй под понятным названием «Денежный поток по дням». Его смысл — сопоставление дневных поступлений и расходов и переход к операциям выбранного дня. Не оставляй пользователю два неразличимых названия со словом «2».

«Экспорт» — действие внутри каждого построенного отчёта. Допустим отдельный пункт общей выгрузки операций, если он нужен существующему интерфейсу, но он не заменяет экспорт конкретного отчёта.

2. ОБЩИЕ ФИЛЬТРЫ И УДОБСТВО

Все виды отчётов должны использовать единый механизм фильтрации и расчёта. На экране видны: «Личное / Бизнес / Всё», период и валютный режим. Остальные фильтры доступны через компактную кнопку «Фильтры» с количеством применённых условий.

Фильтры:
— один или несколько доступных кошельков;
— одна или несколько категорий, с поддержкой подкатегорий, если они есть в текущей модели;
— тип операции, когда отчёт допускает несколько типов;
— валюта;
— поиск по существующим текстовым полям, например комментарию и получателю/плательщику, если такое поле действительно есть;
— включение служебных корректировок отдельной явной настройкой, если модель различает их структурно.

Быстрые периоды: сегодня, вчера, текущая неделя, текущий месяц, прошлый месяц, текущий год, весь период, произвольные даты. Показывай точные даты с годом. Относительные периоды вычисляй на момент открытия, а не фиксируй на 3 октября 2026 года.

По умолчанию обычный отчёт открывается за текущий месяц по текущий день. Переключение фильтра обновляет отчёт; не требуй повторного прохождения нескольких экранов. Обеспечь сброс фильтров, корректную загрузку, понятное состояние «Нет операций» и отдельное состояние ошибки с повторной попыткой. Ошибка загрузки не должна выглядеть как нулевая сумма.

При смене пространства сбрасывай несовместимые выбранные кошельки/категории. Период можно сохранить. Заголовок и видимые условия должны всегда соответствовать фактическому запросу.

Возврат из детализации сохраняет фильтры, сортировку и позицию списка. Сделай сохранение именованного шаблона отчёта и вывод сохранённых шаблонов в каталоге. Сохраняй настройки, а не устаревший снимок сумм. В шаблоне «текущий месяц» даты должны оставаться относительными. Пользовательские шаблоны изолированы по правам доступа.

3. БЫСТРЫЙ ОТЧЁТ «РАСХОДЫ БИЗНЕСА»

Нажатие на этот пункт всегда устанавливает: пространство «Бизнес», расходные операции, все доступные бизнес-кошельки, текущий месяц по текущий день. Отчёт не должен случайно наследовать личные кошельки, выбранную категорию или старый период из другого отчёта.

Определяй бизнес по существующей принадлежности операции бизнес-пространству, а не по словам в названии кошелька или категории. Не зашивай в код список из четырёх кошельков: новые бизнес-кошельки должны включаться автоматически. Не пытайся угадать назначение личной операции по её комментарию.

Вверху покажи сумму расходов по валютам, число расходных операций и самую крупную статью в выбранной валюте. Ниже — категории с суммой, долей и количеством операций; рядом на широком экране можно показывать диаграмму. Доступна группировка «По категориям / По кошелькам / По дням». Для смешанных валют у каждой суммы должен быть явный код валюты.

Нажатие на категорию, кошелёк или день раскрывает подходящие операции. Нужны изменение периода, поиск, сортировка и экспорт. Аналогично работают быстрые «Доходы бизнеса» и «Личные расходы» с соответствующими фиксированными начальными настройками.

4. ПОВЕДЕНИЕ КАЖДОГО ВИДА ОТЧЁТА

4.1. Доходы/расходы по категориям.
Таблица: категория, сумма, доля в выбранной валюте, количество операций. По умолчанию сортировка по сумме по убыванию; разреши сортировать по названию и количеству. Рядом с суммой или под строкой — пропорциональная полоса. Основа доли — вся отфильтрованная выборка этой валюты, а не видимая страница. Категория раскрывает подкатегории/операции без сброса общих условий. Если у операции нет категории, покажи «Без категории», не теряя сумму.

4.2. Структура доходов/расходов.
Кольцевая диаграмма и таблица категорий рассчитаны из одного набора данных. Покажи до 7 крупнейших категорий, остальные объедини только на диаграмме в «Остальное». Нажатие на «Остальное» раскрывает входящие категории. В полной таблице ни одна категория не исчезает. Цвет каждой категории стабилен; легенда и сектор соответствуют друг другу. При нулевом итоге показывай пустое состояние. Отрицательные значения нельзя изображать как отрицательные секторы: покажи их отдельно или используй столбцы с явным объяснением выбранного показателя. Не показывай бессмысленную круговую диаграмму при неположительной базе.

4.3. Сравнение доходов/расходов за периоды.
Два периода, общий набор остальных фильтров. Показатели: сумма A, сумма B, разница в деньгах, изменение в процентах, количество операций. График двух рядов и таблица изменения по категориям. Нажатие на значение раскрывает операции именно соответствующего периода.

По умолчанию сравнивай сопоставимые отрезки: если сейчас 3 октября, 1–3 октября сравни с 1–3 сентября. Полный предыдущий месяц доступен как отдельный выбор. На экране ясно видны оба диапазона и отметка неполного периода. Для произвольных диапазонов разной длительности покажи число дней и среднюю сумму в день, не выдавая их за равные периоды. Для линии доступны «По дням» и «Нарастающим итогом» с явной подписью. Шкалы и единицы должны быть понятны.

При положительной базе процент = (A−B)/B×100. При B=0 и A=0 показывай 0%; при B=0 и ненулевом A — «—, в предыдущем периоде 0», без Infinity/NaN. Если модель допускает отрицательную базу, не показывай вводящий в заблуждение процент: оставь денежную разницу и явную пометку о неположительной базе.

4.4. Доходы и расходы.
За один период показывай поступления, расходы и денежный результат = доходы − расходы. Сопоставь ряды на одном графике с общей шкалой и явной легендой. Предусмотри детализацию по неделям/месяцам и список операций. «Денежный результат» не называй автоматически бухгалтерской или налоговой прибылью: приложение учитывает денежные операции.

4.5. Доходы/расходы по месяцам.
Первый уровень — последние 12 месяцев или выбранный год: месяцы, суммы, количество операций. Текущий неполный месяц явно обозначен. Нажатие на месяц открывает разбивку по дням; нажатие на день — его операции. Итог за месяц и сумма выбранного дня подписаны раздельно. Высота столбцов соответствует суммам. Нулевые дни/месяцы не должны выглядеть как одинаково заполненные большие столбцы. Будущие даты не показывай как уже состоявшиеся нулевые результаты.

4.6. Денежный поток по дням.
За выбранный период показывай парные дневные столбцы «Доходы / Расходы», дневную разницу и итоги периода. Дополнительный режим накопленной разницы допустим с явным названием. Положительные суммы расходов остаются положительными в ряду «Расходы»; отрицательная разница подписывается именно как разница. День раскрывает список операций, как на последних двух скриншотах.

4.7. Настраиваемый отчёт.
Простой конструктор: показатель (доходы, расходы, денежный результат), пространство, период, валютный режим, фильтры, группировка и представление (таблица, столбцы, линия, кольцо там, где это математически корректно). Группировки: категории, кошельки, дни, недели, месяцы; дополнительные — только если есть соответствующие поля в модели.

Разреши добавить несколько именованных групп для сравнения, например «Личные расходы» и «Расходы бизнеса». У каждой группы — свои фильтры и подпись; период и валютная основа сравнения должны быть понятны. Цвет графика соответствует группе. Если группы пересекаются, не складывай их суммы в якобы общий итог: покажи пересечение и отдельный итог по уникальным операциям либо явно сообщи, что группы неаддитивны. Поддержи сохранение, переименование и удаление пользовательского шаблона без удаления операций.

5. ДЕТАЛИЗАЦИЯ И ЭКСПОРТ

По нажатию на сумму/строку/сектор/столбец показывай операции, из которых получился показатель. На компьютере — удобная панель или отдельная таблица, на телефоне — отдельный экран с возвратом. Поля: дата, тип, категория, кошелёк, сумма и валюта, существующий комментарий/контрагент. Итог детализации сверяется с выбранным агрегатом. Пагинация списка не меняет полный итог.

Экспортируй текущий отчёт в настоящий XLSX и CSV. В XLSX предусмотрены листы «Сводка», «Операции», «Параметры»; при конвертации — использованные курсы/даты. Экспорт включает все подходящие операции, а не только загруженную страницу. Суммы — числовые ячейки, валюта — отдельное поле, даты — даты. В параметрах укажи оба периода сравнения, пространство, фильтры, валютный режим, часовой пояс и время формирования. Не переименовывай CSV в XLS/XLSX. Текстовые комментарии/названия не должны исполняться как формулы при открытии в таблицах.

6. ПРАВИЛА ДЕНЕГ И ИСТОРИИ — ОБЯЗАТЕЛЬНО

Рубли, тенге, доллары и другие валюты напрямую не суммировать. По умолчанию считай по валютам отдельно. Можно показывать сводную строку сумм разных валют, но одна диаграмма и её проценты относятся к одной выбранной валюте. Если в проекте есть полноценный механизм конвертации, предложи дополнительный режим с указанием валюты, источника и дат курсов. Не выдумывай курсы. При неполной конвертации укажи непокрытые суммы; не называй частичный результат общим итогом.

Используй точные денежные типы проекта: целые минимальные единицы/BigInt/decimal и правильный scale валюты. Не рассчитывай итог через двоичный float и не округляй каждую строку до агрегации.

Обычные переводы между своими кошельками, включая личное ↔ бизнес, не являются доходами или расходами. Комиссия перевода — расход соответствующего пространства и учитывается ровно один раз через существующую модель. Не суммируй одновременно сохранённый расход-комиссию и дополнительную вычисленную комиссию.

Начальные остатки и технические корректировки не должны автоматически становиться доходом или расходом. Используй структурные признаки действующей модели; не исключай реальные записи только потому, что категория называется «Корректировка». Согласованную модель возвратов/сторно сохрани. Не угадывай связь возврата с расходом по названию категории и не вычитай возврат второй раз.

Исторические операции архивных кошельков и категорий ПО УМОЛЧАНИЮ входят в отчёт за соответствующий период. Архивирование не должно задним числом менять историю расходов. Такие кошельки/категории обозначай как архивные. Для реальных удалённых/отменённых операций соблюдай существующую семантику журнала; не возвращай отменённые записи в отчёт. Не переноси сюда правило «Обзора», который показывает только активные текущие остатки.

Используй дату совершения операции, а не дату её загрузки. Границы дней рассчитывай в часовом поясе приложения/пользователя; конец выбранного дня включён для пользователя, но технически удобен полуинтервал до начала следующего дня. Не отсекай вечерние операции из-за UTC. Используй текущую настройку часового пояса, а не жёстко зашитую дату примера.

Все итоги, таблицы, диаграммы, детализация и экспорт должны использовать одни правила отбора и агрегации. Итог не должен ограничиваться первой страницей API (например, 1000 строками). Не подмешивай незавершённые операции или локальную очередь дважды; сохраняй существующую семантику синхронизации.

7. РЕАЛИЗАЦИЯ И ИНТЕРФЕЙС

Создай общую модель параметров отчёта и переиспользуемый слой выборки/агрегации. Готовые отчёты — разные конфигурации общего механизма, а не 11 несвязанных реализаций денежных формул. При больших выборках используй серверные агрегаты, полную пагинацию или подходящий существующий механизм. Индексы/миграции добавляй только после изучения реальной схемы и необходимости. Соблюдай права доступа и RLS; отчёт «Всё» означает только доступные пользователю личные и бизнес-данные.

При быстрых изменениях фильтров не показывай запоздалый ответ от предыдущего запроса. Переиспользуй кэш аккуратно с учётом всех параметров и обновляй после изменения операций. Не допускай падения всего раздела из-за одной пустой валюты.

Сохрани визуальный стиль текущего приложения и качественные изображения категорий/кошельков. На компьютере располагай связанные диаграмму и таблицу рядом, на телефоне — последовательно. Основные действия доступны одним касанием, фильтры переносятся или раскрываются; не обрезай их справа, как на части примеров. Суммы выровнены, полные значения читаемы, длинные названия доступны, прокрутка не прячет последние строки. Различай доходы и расходы также текстом, а не только цветом. Итоги компактны, без больших пустых блоков.

8. ПРИЁМКА И ПРОВЕРКИ

Проверь на контролируемых тестовых данных вне пользовательского журнала:
— обычные доходы/расходы, две валюты, операция без категории;
— перевод без комиссии не увеличивает доход/расход; комиссия учтена один раз;
— история архивного кошелька сохранена в отчёте;
— операции на обеих границах периода и около полуночи;
— неполный месяц и сравнение с сопоставимым предыдущим отрезком;
— нулевая база сравнения и отсутствие NaN/Infinity;
— детализация и экспорт совпадают с агрегатом;
— выборка больше одной страницы API не теряет суммы;
— пересекающиеся группы настраиваемого отчёта не удваивают общий итог;
— быстрый отчёт бизнеса не наследует личные фильтры;
— сохранённый относительный период корректно переходит в следующий месяц;
— пользователь видит только разрешённые ему данные.

Используй существующие тесты и добавь целевые тесты для этих расчётов и основных переходов. Выполни flutter analyze, применимые тесты, сборку Web; проверь узкий мобильный экран. Открой реальное приложение и покажи скриншоты каталога, «Расходов бизнеса», детализации, сравнения периодов и сохранённого отчёта. Проверь один реальный экспорт.
