## Реализация

- Все 62 исходных PNG скопированы в `assets/business_expenses` с проверкой SHA-256
  manifest; исходные байты, разрешение и прозрачность сохранены.
- Идентификаторы с дефисами сохранены строго из каталога; миграция 015 расширяет
  допустимый формат `icon_id`, добавляет `sort_order` и служебные таблицы пакета.
- Изображения доступны в выборе значков, истории и формах через общий resolver.
  `CatalogMark` показывает объект целиком и декодирует под фактический DPR.
- Существующее дерево сохраняет сворачивание по умолчанию, плюс/минус и действия
  категорий. Отступ — 128 на широком экране и 24 на узком. У «Возврат по договорам
  клиентам» нет кнопки раскрытия.
- В форме бизнес-расхода добавлено дерево выбора с поиском по полному пути.
  Выбор конкретной категории не меняет остальные поля формы.
- Установщик исполняется только административной ролью, проверяет точный бизнес-ID,
  владельца и набор старых ID из резервной копии. Полные пути и явные aliases
  используются для автоматического сопоставления. Использованная неоднозначность
  прерывает всю замену.
- Категории создаются с родительскими связями, перенос ссылок выполняется до
  физического удаления старых строк. Неизвестная FK-зависимость останавливает замену.
  Денежные строки, кошельки, начальные остатки, снимки истории и квитанции не меняются.
- Журнал установки защищает повторный запуск и пользовательские переименования,
  смену значков и удаления. Прежний установщик блокируется для уже заменённого
  бизнес-пространства. Приложение не устанавливает справочники при входе.

## Применение и окончательная приёмка

Готовый файл для SQL Editor проекта `finance-app-dev`, роль `postgres`:
`D:\finance_app\.local-backups\business-expenses\APPLY_BUSINESS_EXPENSES.sql`.
Он создаёт схему 015 один раз, запускает тесты с откатом и устанавливает пакет
в конкретное пространство одной транзакцией. В конце повторно вызывает установщик
для проверки журнала. Повторять весь DDL-файл не нужно; отдельный повторный вызов
находится в `RECHECK_INSTALL.sql`.

После исполнения требуется обновить приложение, получить новый снимок скриптом
`tools/read_business_snapshot.ps1`, выполнить `tools/verify_business_install.py`,
перезапустить сервер и повторить чтение. Проверить реальный каталог 62/11/51,
удаление 130 старых строк, идентичность личных категорий, доходов, операций, кошельков
и остатков, а также сохранение после повторного входа. Эти проверки ещё ожидают
административного доступа; реальные счётчики сейчас: установлено 0, удалено 0,
переназначено 0.

Рабочее приложение перезапущено: `http://localhost:8080` (HTTP 200).
Отдельный предпросмотр: `http://localhost:8082/?view=collapsed`.
