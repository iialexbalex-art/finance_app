# Дерево категорий — 4 октября 2026

Изменения внесены в существующее Flutter-приложение. Рабочий адрес:
http://localhost:8080. Используется прежний `config/local.json`, зависимости
обновлены через `flutter pub get` в пределах существующего lock-файла.
Категории и пользовательские операции в Supabase агентом не изменялись.

## Реализация

- Строки имеют значок 64×64 без подложки и обычную высоту от 76 логических
  пикселей. Изображение и название смещаются вместе: 0/128/256 при доступной
  ширине списка от 720 пикселей, 0/24/48 в узком списке. Для старой более
  глубокой истории отступ ограничивается доступной шириной; записи не обрезаются.
- По умолчанию ветви свёрнуты. «+» раскрывает всё поддерево, включая третий
  уровень. «−» скрывает потомков; дочернюю ветвь можно свернуть отдельно.
  Повторное раскрытие родителя раскрывает его поддерево полностью.
- Кнопки раскрытия отделены от меню, имеют доступные названия и состояние
  `Semantics.expanded`. У листьев их нет. Раскрытие хранится в сессии пользователя
  раздельно по ID пространства, типу, роли и ID категории, сохраняется при
  редактировании и смене раздела/пространства. После новой загрузки страницы
  начальное дерево снова свёрнуто.
- На каждом уровне меню владельца: редактирование, архивирование/активация,
  создание подкатегории и назначение родителя. Невозможные действия отключены:
  четвёртый уровень, создание под архивным предком, активация потомка с
  наследованным архивом до активации предка. Собственные архивные флаги потомков
  не переписываются при активации/архивировании предка. Менеджеру меню недоступно.
- Добавлены поиск и фильтр активности. Найденные потомки видны вместе с
  предками; временное раскрытие результатов не меняет обычное состояние дерева.
  Полный путь и длинное имя доступны через подсказку по наведению/касанию.
- Окно назначения родителя содержит поиск по полному пути, отметку текущего
  родителя, выбор по ID и вариант «Без родительской категории». Исключены
  сама категория, потомки, другой тип/пространство, архивные предки и родители,
  превышающие глубину всей ветви. Причина ограничения указана в окне.
- Перенос выполняет один PATCH `parent_id` существующей записи с проверкой
  прежних значений, пространства и типа. Внутренние связи ветви не меняются.
  Сохраняется устойчивый существующий порядок `created_at, id`; после перезагрузки
  порядок тот же. Новое место раскрывается, строка прокручивается в видимую
  область и выделяется на три секунды. До ответа сервера дерево не меняется;
  ошибки оставляют диалог открытым, повторное сохранение блокируется.

## Сервер и сохранность

Новая миграция дерева не нужна. Согласно текущему README схема 001–013 уже
применена пользователем. Миграция 004 обеспечивает проверку циклов и глубины
всей ветви после UPDATE, составной FK пространства/типа и сериализацию записей.
RLS разрешает запись только владельцу; неизменяемые ID, тип и пространство
закрыты для UPDATE. Эти ограничения не ослаблялись.

Операции, суммы и их внешние ключи не затрагиваются кодом переноса.
В тестах проверены неизменность ID, картинки, активности, объекта операции,
category_id и суммы, отсутствие дублей, повторное чтение из сохраняющего fake API.
Это не подменяет проверку перезагрузки страницы на реальной авторизованной базе.

## Изображение

Оригинал `assets/ready-meal.png` из комплекта скопирован без перекодирования в
`assets/category_photoreal/ready_meal_plov_bread_tea_v1.png`. Стабильный ID
`ready_meal_plov_bread_tea_v1` доступен в выборе значка категории. Оригинальный
набор из 146 изображений сохранён; вместе с добавлением доступны 147.
Генератор каталога сохраняет подключение дополнительного значка, но не добавляет
его в старый SQL-набор для автоматического создания категорий.

Подтверждены совпадение байтов/SHA-256, PNG RGBA 1254×1254 и прозрачные пиксели.
Используется существующий `BoxFit.contain`, `FilterQuality.high` и декодирование
исходника под фактический DPR (64 логических пикселя при DPR=3 → 192 физических).
Категория «Еда» и её изображение сохранены.

Для реального назначения подготовлен
`supabase/manual/assign_ready_meal_2026_10_04.sql`. Он обрабатывает только точное
имя «Готовая еда» в расходах двух существующих пространств, не создаёт категории
и журналирует обработанные ID. Повтор не сбрасывает последующий ручной выбор.
SQL выдаёт количество точных совпадений и сообщает об их отсутствии.
**Файл не выполнен:** в доступной конфигурации есть только публичный клиентский
ключ; авторизованная сессия владельца и административное соединение отсутствуют.
Наличие точного имени в реальной базе не подтверждено. Изображение можно
выбрать вручную уже сейчас, независимо от запуска этого SQL.

## Скриншоты и воспроизведение

Снимки сделаны Chrome на отдельном стенде, который использует настоящие
компоненты раздела с контрольным репозиторием и **не обращается к Supabase**:

- `build/qa/category-tree/collapsed.png` — свёрнутое дерево, 1440×900;
- `build/qa/category-tree/expanded.png` — три раскрытых уровня, 1440×900;
- `build/qa/category-tree/parent.png` — настоящий компонент выбора родителя, 1440×900;
- `build/qa/category-tree/mobile.png` — экран 320×900.

Открытие меню, реальные вызовы сохранения диалога и ошибки проверены widget-тестами.
В стенде вид диалога задан начальным параметром для воспроизводимого скриншота.

Стенд: `flutter run -d web-server -t tool/category_tree_preview.dart --web-port=8081`.
Адреса: `http://localhost:8081/?view=collapsed`, `?view=expanded`, `?view=parent`.
`tool/capture_category_preview.dart` снимает свежие вкладки изолированного Chrome
с debug-портом 9227; ширина задаётся до загрузки Flutter, PNG получают время
для декодирования. Рабочее приложение остаётся на **http://localhost:8080**.
