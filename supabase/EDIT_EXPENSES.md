   [202609300006_edit_expenses.sql](migrations/202609300006_edit_expenses.sql).
   Уже применённые миграции повторно не запускать.
2. В отдельном тестовом проекте/ветке с 001–006 выполнить как `postgres`
   [06_edit_expenses.sql](tests/06_edit_expenses.sql), без замены фиктивных UUID.

   Все тестовые данные откатываются. Регрессии 01, 04 и 05 остаются актуальными.
3. Проверить две независимые сессии по
   [06_edit_expenses_concurrency.md](tests/06_edit_expenses_concurrency.md).
4. Перезапустить клиент после применения миграции:

```powershell
cd D:\finance_app
flutter run -d chrome --web-port=8080 --dart-define-from-file=config/local.json
```

Постоянный порт сохраняет origin локального журнала при последующих перезапусках.
Если предыдущий запуск был на другом порту и есть неподтверждённый запрос,
сначала подтвердить его на прежнем адресе. Новый клиент требует поле `revision`
и RPC из 006; до миграции история нового клиента не загрузится.

## Интерфейс

В «Операциях» вся строка истории владельца открывает заполненную форму,
рядом виден значок и подпись «Редактировать». Менеджеру редактирование недоступно.
Владелец может выбрать кошелёк того же пространства, сумму, категорию, дату,
комментарий. «Отмена» до отправки ничего не записывает.

История и поле даты используют «30 сентября 2026». Ручной ввод: день, название
месяца в родительном падеже, год; рядом календарь с выбором года. Разрешены
все даты от 1 января 1 года до 31 декабря 9999 года, включая прошлые и будущие.
На сервер передаётся только `YYYY-MM-DD`, хранение — PostgreSQL `date`.
Нет `toUtc`/`toLocal`, timestamp или часового пояса расхода. Сегодня берётся
из локального `DateTime.now()` только для новой формы; правка использует сохранённую дату.

Смена валюты/масштаба кошелька очищает сумму и показывает новую валюту:
нужно ввести сумму заново, конвертации нет. Старую категорию с архивным предком
можно оставить; другие архивные ветви отсутствуют среди вариантов.
Успешная правка заново загружает историю с первой страницы и остатки всех кошельков.
Порядок истории — дата по убыванию, затем ID по убыванию.

## Сервер и повторы

`edit_expense` проверяет владельца пространства через `auth.uid()` независимо
от интерфейса. У клиента по-прежнему нет UPDATE/INSERT/DELETE на `expenses`.
Сумма — положительный bigint, передаётся строкой, Flutter использует BigInt.
Проверяются пространство кошелька, тип/пространство категории и вся новая
цепочка предков. Ожидаемая валюта клиента сверяется с серверным кошельком.

Одним UPDATE меняются только разрешённые поля и UUID `revision`. ID, автор,
время создания, пространство и исходный request_id сохраняются. Остатки
вычисляются из строк расходов, поэтому перемещение атомарно меняет вклад
в оба кошелька. Снимок кошелька/валюты обновляется только при смене кошелька,
путь категории — только при смене категории. Сумма, дата и комментарий
не переписывают снимки справочников.

Клиент перед отправкой сохраняет неизменяемый запрос с UUID и исходной версией
в локальный журнал. Ключи разделены по пользователю, пространству и UUID запроса:
две вкладки не затирают журналы друг друга. Старый журнал 005 читается при обновлении.
После потери ответа форма сохраняет значения, блокирует их изменение и предлагает
«Повторить сохранение». Неопределённый уже отправленный запрос нельзя отменить
как несуществующий: сначала необходимо получить подтверждение его результата.
F5 на том же origin восстанавливает запрос. Несколько оставшихся запросов
предлагаются по очереди. До отправки несохранённые изменения формы после F5 теряются.

Закрытая `finance_private.expense_edit_requests` хранит параметры и снимки до/после,
обеспечивает повтор даже после следующих правок. Изменённые параметры при том же
UUID отклоняются `P1002`. Исходная версия формы сверяется с текущей под блокировкой:
другая успешная правка вызывает `P1003`; молчаливой перезаписи нет. Пользователь
видит свои поля для сверки, затем отменяет форму, обновляет историю и открывает
актуальную запись. Автоматическое слияние не выполняется.

Для CREATE добавлена отдельная исходная квитанция: повтор создания после правки
не дублирует расход и не сравнивается с уже изменёнными полями. Существующие строки
получают квитанции при миграции. Обе таблицы квитанций закрыты от клиентов.
Общая guard-строка из 004 сериализует правки со сменой справочников/прав.
`40001`/`40P01` повторяются с теми же параметрами; права проверяются и при повторе.

## Проверки

Flutter-тесты покрывают формат и границы дат, високосный день, локальное сегодня,
календарь, заполнение формы, отмену, смену валюты, архивную прежнюю категорию,
повторы с восстановлением формы, конфликт, сортировку и оба остатка на подменённом
репозитории, права интерфейса, размеры 320×568/1440×900, поздний ответ при смене
пространства. HTTP-тест проверяет RPC, строковую сумму выше точности JS Number,
версию, токен сессии и одинаковые параметры повторов.

SQL-тест 06 подготовлен для прав владельца/менеджера/чужого владельца,
принадлежности справочников, сумм, двух остатков, валюты, снимков, сохранения
идентичности, повторов, устаревшей версии и дат под разными TimeZone.
Миграция, SQL-тесты и реальные конкурентные сессии агентом не запускались.
Flutter-заглушки не подтверждают серверные гарантии.

После SQL проверить в браузере реальные сессии, F5, потерю ответа, две вкладки
с одним расходом, смену кошелька/валюты и архив предка. Результаты автоматических
проверок текущего изменения записаны в [PLAN.md](../PLAN.md).
