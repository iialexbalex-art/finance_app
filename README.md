# Финансы

Раздел владельца «Настройки → Резервные копии»: история действий, сохранение,
скачивание и восстановление. Код готов; для работы требуется установка 018
после проверенной копии БД и подключение серверного исполнителя/хранилища.
Порядок установки: [BACKUPS_SETUP.md](BACKUPS_SETUP.md).
Фактические результаты: [BACKUPS_RESULT.txt](BACKUPS_RESULT.txt).
Перед новой правкой запускайте `python tools/project_checkpoint.py create`.

Flutter-приложение для браузера. Разделы владельца: «Обзор», «Кошельки», «Доходы», «Расходы», «Переводы», «Категории».
Навигация адаптируется к ширине окна. В кошельках три группы: «Наличные», «Счета», «Карты».
Раздел «Отчёты»: быстрые бизнес-отчёты, каталог, фильтры, динамика, детализация,
сравнение периодов, локальные пользовательские шаблоны и экспорт XLSX/CSV.
Реализация и результаты проверок: [REPORTS_IMPLEMENTATION.md](REPORTS_IMPLEMENTATION.md).
В «Категориях» доступны сворачиваемое дерево с адаптивными отступами,
меню на каждом уровне и перенос всей ветви через поиск родителя.
Результаты проверок, скриншоты и статус назначения картинки «Готовая еда»:
[отчёт обновления](design/category-tree-update/IMPLEMENTATION_REPORT.md).
Доступны пространства из Supabase и реквизиты кошельков выбранного пространства.
Владелец может создать кошелёк: название, группа, RUB/KZT/USD/EUR/THB/EGP/TRY.
Менеджер видит только кошельки, разрешённые RLS, без кнопки создания.
Владелец может задать и изменить начальный остаток существующего кошелька.
«Не задан» отличается от нуля; сумма передаётся строкой и обрабатывается BigInt.
Менеджеру остатки не показываются. В «Расходах» доступны создание и история,
серверные фильтры по кошелькам, ветвям категорий (включая архив) и периоду.
Владельцу — редактирование нажатием на строку и итоги по валютам за весь выбор.
Текущие остатки и итоги групп показаны владельцу отдельно по валютам. Нажатие
на строку открывает реквизиты кошелька. Архив вынесен в отдельный список и не
участвует в активных итогах или выборе для новых операций. Удаление выполняется
только для свободного кошелька; история и локальная очередь запросов блокируют его.
На широком экране «Наличные», «Счета» и «Карты» расположены тремя колонками;
строки участвуют в общей прокрутке страницы, а итоги остаются видимыми. Изображения
кошельков и категорий отображаются без подложки в области 64×64 из исходников
в исходном разрешении от 1254 px. Flutter декодирует локальный PNG под фактический
DPR экрана без промежуточного 256/512 px файла. Три утверждённых оригинала
подключены без изменения байтов: `card_sber_green`, `safe_steel_photo` и
`cat_exp_food`. Повторный выбор раздела «Кошельки» закрывает открытые реквизиты.
Дата в истории и форме: «30 сентября 2026». Доступны ручной ввод и календарь
в диапазоне 1–9999 годов; новая запись получает сегодняшнюю локальную дату.
Выбор другого кошелька с иной валютой требует заново указать сумму, без конвертации.
Валюта существующего кошелька не меняется.
Вход по email и паролю работает через Supabase Auth. После входа открываются
разделы приложения; «Выйти» завершает сессию на текущем устройстве.
Категории разделены на вкладки расходов и доходов. Названия и значки кошельков
в любой истории актуальны; снимки операций и квитанции не переписываются.
В создании/правке категории любого уровня и кошелька — цветная сетка с поиском
по русским названиям/синонимам и группами. Каталог кошельков содержит 113 вариантов:
9 банковских знаков, 89 прежних предметных PNG и 15 утверждённых HQ-изображений
банковских карт и копилок. Прежние wallet ID сохранены. В истории основной значок —
категория, уменьшенный — кошелёк. Изменения справочника видны в старых операциях.
Источники, лицензии и недостающие банки: [каталог](assets/licenses/COLOR_CATALOG.md).

## Запуск

Новый пакет бизнес-расходов (62 категории и 62 PNG) подготовлен 6 октября 2026.
Реальная замена требует применения миграции 015 и целевого установщика как postgres;
до применения база сохраняет прежний список. Код не запускает установку при входе.
Точный статус, резервная копия и проверки:
[отчёт бизнес-категорий](design/business-expenses-pack/IMPLEMENTATION_REPORT.md).

Миграции 001–013 применены пользователем, SQL-тест 13 прошёл, набор из 18 личных
и 4 бизнес-кошельков установлен. Повторно запускать миграции и установщик не нужно.
Текущая доработка интерфейса использует схему 013; миграция 014 не требуется.

Доходы и переводы доступны только владельцу. Перевод с комиссией сохраняется
атомарно; комиссия редактируется через перевод. Текущий остаток включает
начальный, доходы, расходы и обе стороны переводов, включая будущие даты.
Разные валюты суммируются отдельно. Сценарий приёмки: [PLAN.md](PLAN.md).

Локальные настройки находятся в `config/local.json` (исключён из Git).
При переносе проекта скопируйте `config/example.json` в `config/local.json`
и заполните `SUPABASE_URL` и `SUPABASE_PUBLISHABLE_KEY` параметрами проекта.
В примере значений нет. Используется только клиентский publishable key.

```powershell
cd D:\finance_app
flutter pub get
flutter run -d chrome --web-port=8080 --dart-define-from-file=config/local.json
```

Оставьте терминал открытым, пока работает приложение. Для остановки нажмите `q`.
Используйте `http://localhost:8080` и прежний профиль Chrome: журнал запросов
хранится в браузере для конкретного адреса и профиля. Не очищайте данные сайта.
При запуске Flutter с отдельным временным профилем открывайте этот же адрес
в привычном Chrome, чтобы использовать его сохранённый журнал.

## Проверки

```powershell
flutter analyze
flutter test
flutter test --platform chrome test/money_test.dart test/opening_balance_repository_test.dart
flutter test --platform chrome test/expense_money_repository_test.dart test/expense_edit_test.dart
flutter build web --dart-define-from-file=config/local.json
```

Результат сборки — `build/web`. Исходные документы сохранены в `REQUIREMENTS.md` и `PLAN.md`.

На вкладке «Обзор» владелец одновременно видит личные и бизнес-кошельки. Таблицы
используют серверный расчёт текущих остатков, исключают архив и показывают итоги
отдельно по валютам для каждого пространства и для общего объёма средств.

Тесты проверяют авторизацию, форму кошелька, права на показ кнопки, сетевые ошибки,
поздние ответы, очистку при выходе и адаптивный интерфейс. HTTP-транспорт Supabase
подменён в тесте: проверяются запросы с токеном сессии, фильтры и поля INSERT.
Вход, применение миграций 001–013 и прохождение SQL-теста 13 подтверждены пользователем.
Список автоматических результатов и оставшихся ручных проверок находится в `PLAN.md`.

Дополнительный SQL для начальных остатков не нужен: точное строковое чтение
использует [PostgREST cast `amount_minor::text`](https://postgrest.org/en/stable/references/api/tables_views.html#casting-columns).
INSERT/PATCH передают целое число минимальных единиц JSON-строкой.

Подключение выполнено по [официальной документации Supabase](https://supabase.com/docs/reference/dart/initializing).
